# Привилегированные операции и аудит

`rfw` вызывает системный `firewall-cmd`. Права root нужны потому, что
`firewall-cmd` изменяет общесистемную конфигурацию firewall; это не особое
требование самой `rfw`. Команды только для чтения могут не требовать `sudo`.

Для обычного использования:

- команды, изменяющие правила, запускайте через `sudo`, а не через общий root-аккаунт;
- перед изменением проверяйте `--dry-run`;
- используйте обычный системный журнал `sudo`/journal, чтобы видеть, кто запускал команду.

`rfw` не ведёт собственного журнала аудита. На серверах с формальными требованиями администратор может дополнительно настроить `auditd` и уже используемый в организации централизованный сбор журналов. Это дополнительная инфраструктура, а не требование `rfw`.

Устанавливайте бинарник из известного commit или release и проверяйте контрольную сумму либо подпись. Открытый код упрощает проверку, но сам по себе не доказывает соответствие установленного бинарника проверенному исходному коду.
