# rfw

[English version](README.md)

Реализованный scope, намеренные ограничения и следующая работа — в
[плане развития](TODO.ru.md).

`rfw` — небольшая командная утилита для `firewalld` на RHEL, Rocky Linux и
AlmaLinux. Она не управляет nftables напрямую: это уменьшает риск конфликтов с
firewalld и делает поведение предсказуемым.

## Быстрый старт

```console
rfw status
rfw zones
rfw zone show public
rfw list --zone public
rfw delete 2 --zone public
rfw open 443/tcp
rfw open service https
rfw open 8443/tcp --timeout 10m
rfw open 51820/udp --zone public
rfw close 8080/tcp --runtime
```

По умолчанию `open` и `close` применяют точечное изменение и к активной
runtime-конфигурации, и к постоянной конфигурации. Изменение действует сразу и
сохраняется после перезагрузки. `--runtime` или `--permanent` ограничивают
изменение одним слоем.

`open --timeout DURATION` создаёт временное runtime-разрешение — например, для
короткого окна обслуживания. Его нельзя сочетать с `--permanent`; после
перезагрузки такое разрешение не сохраняется.

С `open`, `close` и `delete` параметр `--dry-run` покажет точные планируемые
вызовы `firewall-cmd`, но не изменит firewall.

### Безопасное применение изменений

На рабочем хосте сначала посмотрите план от root, и лишь затем применяйте его:

```console
sudo rfw zones
sudo rfw open 443/tcp --zone public --dry-run
sudo rfw open 443/tcp --zone public
```

`--dry-run` не меняет правил. Для `delete` rfw всё ещё читает зону, чтобы
разрешить номер правила, но ничего не удаляет. `rfw` никогда автоматически не
вызывает `reload`, `complete-reload` или `runtime-to-permanent`.

## Номера правил: область и ограничения

В firewalld нет глобального, постоянного номера правила, как в UFW.
Конфигурация состоит из независимых объектов: ports зоны, services, rich rules,
source bindings, policies и других. Поэтому номер имеет смысл только внутри
одного списка и только в конкретный момент времени.

`rfw list --zone public` сейчас нумерует только явные port-разрешения этой
зоны. Номера отсортированы, временны, и список перечитывается непосредственно
перед `rfw delete NUMBER --zone public`. Такой номер не идентифицирует service,
rich rule, policy, NAT либо правило другой зоны.

Это намеренно: иллюзия общего стабильного номера могла бы удалить не тот
объект. Будущий интерфейс rich rules должен использовать полную явную
спецификацию правила либо идентификаторы, которыми владеет rfw, а не общий
порядковый номер хоста.

`close` удаляет ранее добавленное разрешение порта; это не абсолютное правило
запрета. Трафик всё ещё может разрешаться сервисом, другой зоной или rich rule.

Для явного endpoint используйте порт, например `8443/tcp`; для определения
сервиса firewalld — service, например `https`. Рекомендуемое удаление так же
явно: `rfw close 8443/tcp` или `rfw close service https`.

При SSH-подключении `rfw` не позволит закрыть порт текущего SSH-сеанса без
явного `--force`. Используйте `--force` только при наличии консольного доступа.

## Зоны

Firewalld применяет правила в зонах, выбираемых по интерфейсу или source-адресу.
`rfw zones` показывает активные привязки, а `rfw zone show ZONE` — все объекты
зоны. Для безопасности `delete` всегда требует явный `--zone`.

Для `open` и `close` `--zone` можно не указывать только когда активна ровно
одна зона. При нескольких активных зонах rfw остановится и попросит `--zone`:
это предотвращает случайное изменение политики не того интерфейса.

`rfw doctor` работает только на чтение: показывает состояние firewalld и зон,
а также предупреждает о BPF network hooks. BPF-программы находятся вне модели
firewalld, поэтому `rfw` их не изменяет.

## SELinux

Firewall и SELinux — независимые слои. Открытый порт лишь разрешает пакетам
достичь хоста; политика SELinux всё ещё может запретить confined-сервису
bind/accept/connect. `rfw doctor` показывает текущий режим SELinux, но никогда
не меняет booleans или port labels. Если приложению нужен нестандартный порт,
следует осознанно использовать документацию конкретного сервиса и `semanage port`.

## Сборка и тесты

Собрать компактный самостоятельный бинарник:

```console
mkdir -p dist
CGO_ENABLED=0 go build -trimpath -buildvcs=false -ldflags='-s -w' -o dist/rfw ./cmd/rfw
```

Готовый файл будет в `dist/rfw`. `-s -w` убирает debug symbols; для
development-сборок с более подробными stack traces этот параметр можно убрать.

Запустить тесты:

```console
go test -buildvcs=false ./...
```

`rfw` вызывает системный `firewall-cmd`; для изменения правил обычно нужны
права root.
